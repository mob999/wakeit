# AND DAG tasks

Use one Task for an entire inline graph. Keep its ID, revision and paused state when editing. Obtain actual Runner names/IDs, installed Agents and allowed working directories before writing nodes. Use `wakeit schema task` for the current schema. The CLI uses the same `task apply`, `task trigger`, `run watch`, `run cancel` and `run retry` commands as ordinary Tasks.

Start from the independently packaged [DAG template](../assets/task-dag.yaml), replacing its Runner names, Agent IDs and directories with actual allowed values. Apply with `wakeit --json task apply --file task-dag.yaml`; use `--expect <revision>` for edits. Creating or updating a scheduled graph does not imply permission to trigger it.

A DAG config has common `version: 1`, `id`, `name`, `schedule`, `enabled`, `execution`, plus `dag.nodes` and optional `dag.results`. It must not define top-level Runner, Agent, cwd, prompt, parameters or Session. Each node contains a stable ID, name, `pre` list and its own execution fields. Give copied nodes new IDs. Names may change without changing references.

All roots start together, subject to Runner capacity and Session locks. Only AND is supported: every predecessor must succeed. Failure skips impossible descendants while independent branches continue. Never trigger, retry or cancel an internal execution independently; a retry starts a new whole round from the current Task definition. Optional node `max_retries` (0–10, default 0) enables bounded automatic retries. Never bypass unsuccessful predecessors.

To use upstream output, add the predecessor explicitly, then insert `{{ nodes.<ancestor-id>.result }}` into the consumer's prompt. Only ancestors in the same round are allowed. Strings remain literal and objects become JSON; no expressions or recursive template expansion. Missing, empty, expired, incomplete or persistently truncated results fail the consumer before Agent submission. Expanded instructions are limited to 1 MiB. Do not substitute logs for results.

Omit `dag.results` to use every leaf, or provide a nonempty explicit subset. Reports keep definition order. All nodes successful means succeeded; selected outputs successful with another unsuccessful branch means warning (Watch exit 0). An unsuccessful selected output means failed. unknown is nonterminal until the actual uncertain node is reconciled. Whole cancellation/timeout waits for confirmation; graph timeout starts at first claim and defaults to 1h, as do individual node timeouts.

Validate through workspace-scoped `POST /tasks/validate` with `{config}` when available. Resolve reported field/node/cycle errors; final apply validates atomically again. Revision conflicts require reading the latest definition and preserving intended changes, not blindly overwriting. Do not create or trigger a task merely to validate it.

`GET /runs/{parent}` includes frozen nodes and selected reports. `GET /runs/{parent}/nodes/{node}` returns the actual execution or null. Its events use the existing `after` cursor, at most 500 per batch. Parent event streams label node IDs and original execution identity. For continuation, use that actual node's `session.command`; the parent itself has no Agent session.

WebUI offers Tasks → Plus → DAG task: drag or choose an installed Agent on a specific Runner, connect ports to edit `pre`, and click a node to open its floating inspector. The table uses the same inspector; output settings also use that panel. Nodes and connections can be moved, selected and undone; layouts are explicitly saved with the Task. `editor_layout` is response/API presentation state outside TaskConfig, YAML, Run snapshots and Runner messages. CLI apply omits it and preserves remaining node coordinates. Steps switch freely with incomplete drafts; Save validates and applies the entire draft. Saved task types cannot be converted. Subgraphs, references to independent Tasks and resuming from a failed node are unsupported.

## DAG node retries

A node may set `max_retries: 3` for up to four attempts. Omitted/0 disables retries. Confirmed execution failures and node timeouts retry after 5/10/20/40/60 seconds with bounded jitter; validation, invalid Session, cancellation and unknown do not automatically retry. Older Runners without the optional state-event retry verdict conservatively do not retry failed executions. The graph timeout includes backoff and never resets. Attempts remain child Runs with their own logs, Trace, result and native Session; default sessions start anew, explicitly bound sessions are reused under the same locks.

While a retry is queued, Operator/Admin may accelerate that exact execution via `POST /runs/{parent}/nodes/{node}/retry` with `{execution_id}`. This does not grant extra attempts. `GET /runs/{parent}/nodes/{node}` lists lightweight `attempts`; optional `?execution=<uuid>` reads a specific attempt of this node. After graph completion only whole-graph retry is supported, using the current Task definition from all roots; historical Runs are never reopened. Migration 0006 replaces the single-attempt index without discarding existing executions.
