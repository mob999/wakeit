# wakeit development conventions

wakeit is unreleased. Keep all product/package versions at 0.1.0 and config/message version at 1. Refactor protocols and database structures directly; do not add compatibility layers. PostgreSQL migrations must be a single complete 0001_initial.sql until release. Local runtime data and credentials must remain ignored. Before replacing local data, back it up and confirm no active Runs; never affect Agent credentials. Track each change with a GitHub Issue, work on a scope-prefixed feature branch using <type>(<scope>)/<description>, for example feat(gateway)/device-auth or fix(runner)/reconnect (do not use a codex/ prefix), and submit a pull request referencing the Issue. Never force push, rewrite pushed commits or tags, or push changes directly to main. Preserve the ghdiff visual baseline in docs/design.md.

Keep product copy focused on user data, controls, and necessary operational errors or consequences. Do not add implementation notes, development history, or automatic-ID explanations to titles, forms, or footers.
